# Phase 07.5 Plan 05 (mid-plan deviation fix): Paraphrase Harness Faithfulness Fix Summary

**Fixed three root-cause mechanisms (distinctness/budget, narrow intent lexicons, literal-reformatting + degenerate questions) in `bank_generator.py`'s `paraphrase()`/`slot_preserving()` that made Plan 05's own credentialed live-LLM regen fall short of REQ-3 (<3 faithful paraphrases for 43/77 CK25 examples) -- all four fixes TDD'd and verified fully offline against scripted LLM doubles, with zero live LLM calls.**

## Performance

- **Started:** 2026-08-03T18:12:00Z
- **Completed:** 2026-08-03T18:47:00Z
- **Tasks:** 4 fix-commits (Changes A/B/C/D) + 1 RED test commit + this SUMMARY
- **Files modified:** 2 code/test files + STATE.md

## Accomplishments

- **Change A (distinctness/budget):** `paraphrase()` now appends a growing "already-produced paraphrases" note to the user message from the 2nd accepted candidate on, explicitly asking for a genuinely NEW, distinct phrasing, and raises `max_attempts` from `k*3` to `k*5`. The default (`client=None`) construction path also bumps `OpenAICompatibleClient`'s temperature from the inherited 0.1 to 0.7. Proved via two scripted doubles: `_NoveltyProbeClient` (which only diversifies once the novelty note is present in the prompt -- demonstrating the prompt change itself, not just more attempts, is necessary) and a `ScriptedLLMClient` needing 7 rejects + 3 accepts = 10 calls (beyond the old `k*3=9` budget, within the new `k*5=15`).
- **Change B (narrow lexicons):** Broadened `grouped_aggregation`'s intent_lexicon with "over"/"greater than"/"greater than or equal"/"exceeding"/"at minimum", and `negation`'s with "lack"/"lacks"/"do not have"/"have no"/"not have" -- fluent synonyms the original 3- and 5-token lexicons wrongly rejected. `top_n`/`offset` direction logic untouched.
- **Change C (literal reformatting):** `slot_preserving`'s filler-substring check now normalizes a decimal comma to a period and collapses whitespace runs (`_normalize_filler_text`) on BOTH the bound filler and the candidate paraphrase before comparing -- so a model-reformatted `"0.38 EUR"` still matches a `"0,38 EUR"` filler. No digit or currency code/symbol is ever stripped: a value-changing (`"0,39 EUR"`) or currency-changing (`"0.38 USD"`) paraphrase still fails the check, preserving faithfulness.
- **Change D (degenerate questions):** `_is_degenerate_value_label()` flags a subject whose own `rdfs:label` is a bare monetary/numeric value (e.g. `"0,38 EUR"`, `"€0.38"`) -- narrowly matched so a genuine name (`"Ratt Hartmann"`, `"Widget-1"`) never matches. Wired into `_candidates_lookup`/`_candidates_value_object` via `_sample_labels`'s new `exclude=` parameter. **Critical implementation detail found during TDD:** filtering must happen AFTER the per-predicate shuffle, not before -- filtering-before-shuffling desyncs the shared per-shape `rng` stream and cascades into >10 unrelated lookup examples changing their sampled fillers. Filtering after shuffling keeps every other predicate's sampling byte-identical; verified via a direct fresh-vs-committed diff showing exactly the 4 known degenerate examples (`"What is the amount of 0,38 EUR?"`, `"...2,60 EUR?"`, `"What is the currency of 4,46 EUR?"`, `"...5,60 EUR?"`) drop, with zero unrelated drift (73/77 examples remain).
- Added 8 new offline/scripted tests to `test_bank_generator.py` covering all four changes, including a "richer" scripted double (`_NoveltyProbeClient` + a hand-crafted `ScriptedLLMClient` response list mimicking decimal-reformat + one value-changing corruption) per the plan's TDD requirement. Updated the two pre-existing committed-artifact byte-exact-equality regression tests (`test_committed_ck25_bank_matches_fresh_regeneration`, `test_committed_ck25_report_matches_fresh_regeneration`) to structural (question/query/shape subset; per-shape kept/dropped delta) checks, since generation semantics legitimately changed (Change D drops 4 examples; Change A's novelty note changes the scripted echo double's exact paraphrase text) -- keeping their original "committed artifact must not silently drift from generator logic" intent per the plan's own explicit guidance, without editing the committed `.yml`.

## Issues Encountered

- **Shared-RNG cascade (self-caught, fixed before commit):** the first `_is_degenerate_value_label` wiring filtered labels BEFORE `rng.shuffle`, which changed the shuffle's input length for the "amount"/"currency" predicates and silently desynced every subsequent predicate's shuffle draws sharing the same per-shape `rng` -- surfaced immediately by `test_committed_ck25_bank_matches_fresh_regeneration` failing with 16 unexpected "new" examples (unrelated predicates like `email`/`phone`/`reliabilityIndex` producing different sampled fillers). Fixed by shuffling the full unfiltered list first, then filtering, then capping -- verified via a direct fresh-vs-committed diff showing exactly the 4 expected degenerate drops and zero unrelated changes.
