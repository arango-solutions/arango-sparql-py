# Phase 07.5: NL→SPARQL query-first synthetic few-shot bank — Specification

**Created:** 2026-07-30
**Ambiguity score:** 0.18 (gate: ≤ 0.20)
**Requirements:** 6 locked

## Goal

A build-time generator produces a per-ontology `(question, gold-SPARQL)` few-shot bank **query-first** from an ontology's TBox, loaded through the existing BM25 `FewShotIndex` seam, so NL→SPARQL adapts to any new ontology without hand-curation — validated by the *same generator* lifting held-out human questions on two independent ontologies (CK25 + QALD).

## Background

Domain dominates NL→SPARQL quality (a fixed recipe swung 60%→13% between a readable and an opaque schema; the model floors at 0.2% on DBpedia/QALD). The one proven lever is few-shot retrieval (+19pt, BM25 — NL-FEW-02), but the only bank today is a hand-curated `tests/nl2sparql/eval/fewshot_bank.yml`; nothing generates a per-ontology bank. Phase 07.1 retired *question-first synthetic corpus generation for eval* (oracle + external-validity risks) and explicitly put "the synthetic generator" out of scope. Phase 07.4 built a TBox walker (`build_predicate_index`) that classifies each predicate's shape (value_object / category_instance / linked_entity / literal) and, on its documented null, recommended "targeted surfacing, not a full dump." This phase re-opens 07.1's fence in a narrower, safer form — query-first construction for a few-shot *pool*, not question-first for *eval* — reusing the 07.4 walker as query-construction raw material. Full design: `.planning/research/query-first-synthetic-fewshot-bank-design.md`.

## Requirements

1. **Query-first template generator**: a build-time generator emits a per-ontology bank from a TBox using compositional templates.
   - Current: no synthetic generator exists; the only bank is a hand-curated `fewshot_bank.yml`.
   - Target: a generator that, given a TBox, emits `<ontology>_fewshot_bank.yml` in the existing `FewShotIndex` format, instantiating ≥7 ontology-agnostic compositional SPARQL template shapes (lookup, value-object, category-filter, COUNT, top-N, OFFSET, negation, 2-hop) with predicate/class slots filled from the TBox (reusing 07.4's shape classification).
   - Acceptance: running the generator on the CK25 TBox produces a valid `fewshot_bank.yml` whose every query parses and transpiles; ≥7 distinct template shapes are present.

2. **Data-bound, non-empty examples**: generated examples return results against the ontology's data.
   - Current: N/A (no generator).
   - Target: entity/value slots filled by sampling the live instance data; each candidate executed; only non-empty survivors kept.
   - Acceptance: 100% of generated bank queries return ≥1 row / `true` / a meaningful count when executed against the source data — zero empty-result examples.

3. **Faithful, natural questions**: paired question templates plus LLM paraphrases.
   - Current: N/A.
   - Target: each query carries a templated question and K ≥ 3 natural paraphrases all mapping to that same query; a sampled faithfulness audit.
   - Acceptance: on a random sample of ≥ 20 pairs, an LLM-judge (or human) confirms the question matches the query for ≥ 95%.

4. **Drop-in per-ontology integration**: the generated bank loads through the existing BM25 retrieval.
   - Current: `FewShotIndex.from_corpus_files` loads a single curated bank via BM25.
   - Target: a generated per-ontology bank file loads unchanged through `FewShotIndex`/BM25; an eval config arm points at it.
   - Acceptance: an eval arm using the generated CK25 bank runs end-to-end and retrieved examples appear in the `NLQueryEngine` prompt's `## Examples` section.

5. **Cross-ontology generalization (one generator, both domains)**: the same generator runs on CK25 and QALD.
   - Current: N/A.
   - Target: the one generator runs unmodified on both the CK25 and DBpedia TBoxes, producing two banks with no ontology-specific code branches.
   - Acceptance: both banks generate from the same code path; inspection confirms no CK25- or DBpedia-specific hardcoding in the generator.

6. **Directionally-graded lift with overlap audit** (the adopt/kill decision): measured mechanistically + directionally on held-out human questions.
   - Current: this lever has never been measured.
   - Target: a held-out measurement on CK25 (49) and QALD (514) with a query-shape overlap audit; the generator built blind to the held-out questions and run once.
   - Acceptance (**adopt**): shape-coverage ≥ 70% of held-out failing cases' gold shapes; CK25 net pass-delta > 0 across 3 runs with zero regressions; the delta stays > 0 after excluding near-duplicate-shape examples; QALD non-regression. **Kill** if CK25 delta ≤ 0 after overlap-exclusion, or only one ontology shows any signal.

## Boundaries

**In scope:**
- The query-first template generator (compositional templates + TBox slot-filling + data-binding + paraphrase).
- Per-ontology bank files loaded via the existing BM25 `FewShotIndex` (engine-side; Cypher inherits).
- The held-out measurement on CK25 + QALD, run by the same generator, with the overlap audit (extend `test_fewshot_bank_disjoint` to shape-level).

**Out of scope:**
- Question-first generation (LLM invents the question then writes its own gold) — the oracle problem 07.1 retired.
- Using the generated bank *as an eval or a validity certificate* — it is a prompting aid; validity comes only from held-out human sets.
- The (a′) validated-LLM diversity add-on — deferred; added only if coverage measurement shows the templates are too narrow (design doc §Q1).
- The production query-time run-and-retry self-repair loop — separate parked lever (`execution-feedback-self-repair-lever.md`).
- Fixing QALD's entity-grounding floor — an orthogonal bottleneck, not this lever's job.
- Dense retrieval — BM25 is the proven primary; dense stays parked.
- A powered statistical-significance gate — the benchmark reality (CK25 underpowered, QALD orthogonal) cannot provide one; grading is mechanistic + directional by design.

## Constraints

- Generator must be schema-/language-agnostic — no CK25/DBpedia-specific logic — so Cypher inherits it and it transfers to the CDF project.
- Reuse the existing `FewShotIndex`/BM25 and `fewshot_bank.yml` format — no new retrieval code.
- Build-time only: zero query-time latency, no query-time DB or LLM dependency.
- Assumes representative instance data at build time; a TBox-only fallback (ungrounded, lower quality) is the documented degrade path if data is absent.
- The generated bank must stay disjoint from the held-out eval questions (shape-level disjointness gate).
- Non-regression: W3C DAWG query-eval coverage ≥ 96.4%, the SPARQL→AQL transpiler package unchanged, scripted configs remain the no-network CI default, no secrets committed.

## Acceptance Criteria

- [ ] Generator emits a valid `<ontology>_fewshot_bank.yml` from the CK25 TBox; every query parses and transpiles.
- [ ] ≥ 7 distinct compositional template shapes appear in the generated bank.
- [ ] 0 empty-result examples — 100% of generated queries execute non-empty against the source data.
- [ ] Each query has ≥ 3 natural paraphrases; sampled faithfulness ≥ 95% on ≥ 20 pairs.
- [ ] Generated bank loads via `FewShotIndex`/BM25 and appears in the prompt's `## Examples` section.
- [ ] The same generator produces both CK25 and QALD banks with no ontology-specific branches.
- [ ] Shape-coverage ≥ 70% of held-out failing cases' gold shapes.
- [ ] CK25 net pass-delta > 0 across 3 runs, zero regressions, and > 0 after overlap-exclusion.
- [ ] QALD non-regression; the overlap audit reports the lift both with and without near-duplicate-shape cases.
- [ ] Non-regression: W3C DAWG ≥ 96.4%, transpiler package unchanged, scripted CI default preserved.
