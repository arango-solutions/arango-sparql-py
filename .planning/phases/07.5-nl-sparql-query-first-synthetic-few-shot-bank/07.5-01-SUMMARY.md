## Accomplishments
- `build_predicate_signals` adds `orderable` (range-IRI-only, mechanical) and `optional_relation` (data-driven, both-present-and-absent probe) signals in a new eval-side `PredicateSignals` sibling struct — the engine's `GroundedPredicate` is byte-unchanged and `runner.py`'s existing `build_predicate_index` consumer is untouched.
- Empirically confirmed against the real CK25 vendored TBox+data: all 7 `xsd:decimal` predicates orderable=True, `pv:name`/`addressCountry` (xsd:string) orderable=False; `pv:country` (domain Supplier) is a genuine optional relation (227 with / 23 without), `pv:hasManager` (domain Employee) is not (all 47 have one); TBox-only (`data_ttl=None`) degrades every predicate's `optional_relation` to False without crashing.
- `bank_generator.py` scaffolds the generator's type backbone: a frozen `ShapeTemplate` dataclass (`name`/`applies`/`build_sparql`/`question_template`/`semantic_slots`/`intent_lexicon`) and an ordered 9-name `SHAPE_CATALOG` (lookup, value_object, category_filter, scalar_count, grouped_aggregation, top_n, offset, negation, two_hop — `grouped_aggregation` kept separate from `scalar_count` per the spike's carry-forward regression lesson) plus a stubbed `generate_bank()` signature.

## Decisions Made
- optional_relation probes exact `rdf:type` match against the predicate's declared `rdfs:domain` class — no subclass walk (mirrors 07.4's own domain-exact-match discipline documented in RESEARCH.md); this is why CK25's `hasSupplier`/`hasCategory` (declared domain `pv:Product`, but no instance is literally typed `pv:Product` — only its subclass `pv:Hardware`) correctly resolve to "unavailable" rather than a false positive, while `pv:country` (domain `pv:Supplier`, and real `pv:Supplier`-typed instances exist) resolves correctly.
- The name-anchoring guard in `verify_generated_bank.py` derives its allowed-namespace set structurally (namespaces of `owl:Class`/`ObjectProperty`/`DatatypeProperty` subjects) rather than hardcoding CK25's `prodi:` prefix — this matters because CK25's own TBox header declares a `@prefix prodi:` line (for `prodi: a void:Dataset`) even though `prodi:` is genuinely the instance namespace, so a naive "namespace declared in the ontology text" check would have wrongly allowlisted it.
- Kept the top-N strict-extremum probe as an optional per-bank-example `probe:` YAML field (replacing the spike's hardcoded `TOPN_PROBES` dict keyed by question text) so a future generator-emitted bank can carry its own probe inline; the pre-existing spike bank file was left untouched (out of this plan's file scope) and simply has no `probe` field yet.
