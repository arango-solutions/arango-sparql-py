# Phase 07.5 Plan 05 (mid-plan deviation fix #2): two_hop Faithfulness Fix Summary

**Fixed the ONE real bank-faithfulness defect the credentialed judge + manual domain/range adjudication found: the two_hop shape's NL question named only the near predicate, omitting the far predicate the query's `?result` binding is actually reached through. TDD'd fully offline (RED test -> fix -> GREEN), query text unchanged, real-LLM-paraphrase bank on disk untouched.**

## Performance

- **Duration:** ~20 min
- **Tasks:** 1 RED test commit + 1 fix commit (question_template + candidate-builder slot + test relaxation) + this SUMMARY
- **Files modified:** 2 test/code files

## Accomplishments

- **RED:** Added `test_two_hop_question_names_both_predicates` (module-scoped `ck25_bank_and_report` fixture), which re-derives the expected near/far predicate labels straight from each generated two_hop example's own query text (via the real CK25 predicate index, never a hardcoded label string) and asserts both appear in the rendered `question`. Confirmed failing against the pre-fix template (`AssertionError: two_hop question missing far_predicate label 'member of': ...`).
- **GREEN:** Rewrote the `two_hop` `ShapeTemplate.question_template` from `"Which {far_type} is linked to {entity} via {near_predicate}?"` to `"What is the {far_predicate} of the {member_type} whose {near_predicate} is {entity}?"`, and wired a new `member_type=pred.domain` slot into `_candidates_two_hop`'s `template.format(...)` call (`pred.domain == hop_pred.domain` always holds here, since `_applies_two_hop`/the partner filter already require the same shared domain). The query (`_build_two_hop_sparql`) was NOT touched. Example: `"Which Product is linked to Anamchara Foerstner via has product manager?"` -> `"What is the compatible product of the Product whose has product manager is Anamchara Foerstner?"` -- now names both `hasProductManager` ("has product manager") and `compatibleProduct` ("compatible product"), the actual predicate the returned `?result` is reached through.
- Relaxed `test_committed_ck25_bank_matches_fresh_regeneration`'s structural subset check from `(question, query, shape)` triples to `(query, shape)` pairs, since a fresh two_hop question's wording now legitimately differs from the committed (still pre-fix) bank on disk. Query-text equality is preserved byte-for-byte, keeping the test's original "committed bank must not silently drift from generator logic" intent. `test_committed_ck25_report_matches_fresh_regeneration` needed no change (it compares only per-shape kept/dropped counts, which two_hop's wording change does not affect).
- Verified `uv run ruff check` clean on both touched files, and confirmed via `git status`/`git diff --stat` that `tests/nl2sparql/eval/vendored/ck25/generated_fewshot_bank.yml` (the human's uncommitted, non-reproducible real-paraphrase regeneration) carries no additional diff from this work.
