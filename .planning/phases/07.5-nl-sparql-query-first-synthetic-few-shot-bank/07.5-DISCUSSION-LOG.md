## Areas discussed (all 4 selected)

### 1. Generator home & sequencing
- **Options:** eval-harness-first (fast measurement) vs engine-side from the start (Cypher inherits immediately).
- **Initial:** eval-harness-first, promote to engine if it clears the adopt bar.
- **Hole found:** the eval prototype ≠ the production generator (`build_predicate_index` is eval-only); "adapts to any new ontology" implies a production path that eval-first doesn't deliver; promotion under-scoped.
- **Locked (D-01):** three explicit stages — Stage 0 SPIKE gate (2–3 shapes, CK25, does it move any held-out case?), Stage 1 eval prototype (pure functions, CK25+QALD measurement), Stage 2 engine promotion ONLY if the adopt bar clears. Prototype validates the hypothesis; promotion is the product deliverable.

### 2. v1 template ambition
- **Options:** easy single-predicate shapes only (prove pipeline) vs hard compositional shapes from v1.
- **Initial:** include hard shapes from v1, filter what won't construct.
- **Hole found:** filtering silently caps coverage of exactly the hard shapes we care about; hard shapes need richer TBox signal (numeric/orderable, expected-but-optional) than 07.4's 4-way classification.
- **Locked (D-02):** target the full ≥7 shapes; **per-shape yield is a first-class output** (filtering is measured, not silent); derive the extra TBox signals or drop-with-logged-reason.

### 3. Paraphrase & faithfulness model
- **Options:** same NL2SPARQL provider vs separate/cheaper key; K paraphrases.
- **Initial:** same provider, K=3.
- **Hole found:** build-time LLM dependency (not hands-free onboarding); same-model write-then-judge misses the model's own errors — and under-uses the paired-template ground truth.
- **Locked (D-03):** same provider, K=3; faithfulness PRIMARY guard = check paraphrase against the question **template's** known semantics; LLM-judge is a secondary sample check; build-time LLM dependency named explicitly.

### 4. QALD data-binding
- **Options:** live DBpedia endpoint vs vendored snapshot vs TBox-only degrade.
- **Initial:** vendor a bounded DBpedia instance snapshot.
- **Hole found:** a snapshot built from the test entities leaks them into examples (entity-level contamination the shape audit misses); curating a diverse DBpedia slice is disproportionate effort for a benchmark whose bottleneck is orthogonal.
- **Locked (D-04):** CK25 richly data-bound; QALD best-effort / TBox-only; generalization claim rests on "same generator runs + emits valid shapes on DBpedia's TBox," lift measured primarily on CK25. **(D-05)** overlap audit checks both shape AND entity overlap.
