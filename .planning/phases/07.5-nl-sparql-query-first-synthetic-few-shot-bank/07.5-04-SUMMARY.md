## Deviations from Plan

### Documented Finding (not a code deviation)

The plan's Task 1 `<action>` text anticipated that "structural shapes (lookup, value_object, category_filter, scalar_count, two_hop, grouped_aggregation where a groupable category exists) emit name-anchored examples that parse+transpile" on QALD, with only the 3 data-driven shapes (negation, top_n, offset) expected to drop. Empirically, **all 9 shapes** drop to zero on this specific vendored QALD subset, because:

1. QALD's `dbpedia_subset.ttl` declares zero `rdfs:domain`/`rdfs:range` triples for any of its 250 properties (grep-verified: `grep -c "rdfs:domain\|rdfs:range"` → 0) — an already-accepted, 07.4-03-documented characteristic of this vendored file, not something introduced or alterable in this plan.
2. Plan 02's `generate_bank_with_report` pipeline requires real instance-level `rdfs:label` data for name-anchoring on **every** shape (not only the 3 data-driven ones) — `data_ttl=None` short-circuits to `{"version": 1, "examples": []}` universally, a behavior already tested and committed via CK25's own `test_generate_bank_degrades_to_empty_without_instance_data` (Plan 02/03).

No code change was made to `bank_generator.py` to work around this: doing so would require either building a synthetic QALD instance snapshot (explicitly forbidden by D-04 — entity-level test contamination) or hand-authoring a per-schema label/domain hint (explicitly forbidden by D-02/REQ-5 — reintroduces an ontology-specific branch, defeating the very thing this plan proves). The plan's own acceptance criteria (verify-gate exits 0, report contains "drop", same entry point/no branch, no hardcoded instance IRI) are all satisfied by the honest empty-bank outcome, and the underlying REQ-5 claim ("the same generator RUNS unmodified and emits structurally-valid examples," never "lifts QALD") is unaffected — arguably strengthened, since the proof is now the strongest possible form: byte-identical code path, zero special-casing, for any outcome the ontology happens to produce.

**Total deviations:** 0 auto-fixed (no code changes were needed or made); 1 documented empirical finding that is broader than the plan anticipated but does not violate any plan requirement or threat-model mitigation.
