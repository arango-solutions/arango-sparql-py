# Phase 07.6: NL→SPARQL relationship-path grounding — Specification

**Created:** 2026-08-06
**Ambiguity score:** 0.15 (gate: ≤ 0.20)
**Requirements:** 5 locked

## Goal

NL→SPARQL execution-graded CK25 accuracy improves over the current composed ceiling (`grounded + few-shot` = 16/49) by giving the model the *specific relationship path* connecting the question's grounded anchor class to its target — converting a meaningful share of the 16 verified "right-entity, wrong-path" failures (valid SPARQL that executes to empty) into correct navigations, with zero regressions.

## Background

Root-caused from the Phase 07.5 composed-lever evaluation (candidate dump, 2026-08): the composed `grounded + few-shot` arm scores 16/49; **every failure is valid, executable SPARQL — 0 malformed.** Of 31 failures, **16 ground the named entity correctly but navigate the wrong predicate-path** and execute to empty (canonical: ck25-7 "manager of Data Services" used `responsibleFor` off the Department instead of the inverse `memberOf`←Person→`hasManager`).

Today the engine has seam-6 (entity grounding: `grounding_index`/`grounding_prompt_section`) and seam-7 (predicate grounding: `PredicateIndex` with domain/range/shape + a token scorer). Full predicate grounding (07.4) *dumped* the schema and net-regressed via distraction. There is **no path-retrieval capability** — no class-connectivity graph, no shortest-path between two classes, no navigation-hint renderer, no `path_grounding` config seam. An offline Step-0 recall spike (2026-08) confirmed the gold paths are mechanically recoverable from the CK25 TBox (12/16 naive → ~14/16 at depth-3 with subclass-aware nodes + inverse edges + self-revisit), and that a naive exact-class design would silently miss the canonical case. Full design: `.planning/research/relationship-path-grounding-scope.md`.

## Requirements

1. **ClassPathIndex engine seam**: A pure, `pyoxigraph`-free `arango_query_core.nl` seam builds a subclass-aware, inverse-edged class-connectivity graph from a TBox and returns bounded shortest predicate paths between two classes.
   - Current: no path-retrieval capability exists (only seams 6/7); class connectivity is not modeled.
   - Target: a `ClassPathIndex` (mirroring seam-6/7 style — frozen/caller-owned, stdlib-only) with graph build (forward + inverse edges from `rdfs:domain`/`rdfs:range`, `rdfs:subClassOf`-aware node linking, bounded self-revisit for self-referential relations) + `shortest_paths(anchor, target, depth≤3, ≤5)` + a `format_prompt_section` renderer.
   - Acceptance: engine unit tests green; `depth ≤ 3`; at most 5 paths returned; deterministic ordering (length → question-token overlap → lexical); no `pyoxigraph` import on the engine path.

2. **Adapter path seam + composition**: `path_index()`/`path_prompt_section()` on `QueryLanguageAdapter`, composed after the entity block, anchored on real signals.
   - Current: `NLQueryEngine._system_prompt` composes only seam-6/7 blocks.
   - Target: anchor class from the seam-6 grounded entity's `rdf:type`; target from the seam-7 token scorer; the renderer injects a compact navigation-hint block after the entity block, presenting a join/star pattern as a shared-variable join (not a forced A→B→C walk).
   - Acceptance: composed prompt contains the path-hint block when anchor+target resolve; emits `""` (honest no-op) when either is unresolved or no path exists within depth 3.

3. **Eval-side config seam + composed arm**: A `path_grounding:` config block, a composed CK25 arm (`grounded + few-shot + path`), and a scripted plumbing twin.
   - Current: `configs.yml` has grounded / predicate / few-shot / composed arms but no path arm; `run_composed_sweep.py` has no path arm.
   - Target: additive `path_grounding:` read in `runner.py` (mirrors `grounding:`/`predicate_grounding:`); `openai-gpt4o-mini-ck25-grounded-generated-fewshot-path` + scripted twin; the arm wired into `run_composed_sweep.py`.
   - Acceptance: `--dry-run` builds grounding + few_shot + path indices into one `NlPipeline` with no crash; scripted arm is 49/49 plumbing.

4. **Offline path-recall gate**: A committed offline test asserts the class-graph retrieval recovers the gold paths for the empty-result failure set.
   - Current: the Step-0 spike exists as a scratch script only; no committed gate.
   - Target: a committed test asserting **path-recall ≥ 14/16** on the 16 empty-result golds at depth-3 with subclass-aware nodes + inverse edges + self-revisit; "recovered" = the gold predicate-path appears among the ≤5 returned paths.
   - Acceptance: the recall test passes at ≥14/16 offline, no key; runs in the always-on tier.

5. **Credentialed directional lift + non-regression**: A human-run CK25 sweep shows a directional lift over the `g+f` baseline with zero regressions; non-regression gates hold.
   - Current: composed `g+f` = 16/49 (baseline); no path arm measured.
   - Target: the human-run paired sweep (`grounded+few-shot+path` vs `grounded+few-shot`, same session) shows a directional lift with **zero regressions**; adopt/kill recorded in `baseline.json`. W3C DAWG ≥96.4%, transpiler unchanged, no pyoxigraph on engine path, mechanical TBox derivation (no CK25 hand-curation).
   - Acceptance: `baseline.json` carries the paired result; directional lift with c=0 regressions ⇒ ADOPT (not significance-gated — CK25 n=49 is underpowered, mirroring 07.4/07.5); `test_coverage_gate.py` green.

## Boundaries

**In scope:**
- `arango_query_core.nl` seam-8 (`ClassPathIndex`: subclass-aware + inverse-edged graph, depth-≤3 shortest-path, ≤5-path budget, renderer)
- Adapter wiring (`path_index`/`path_prompt_section`) + composition after the entity block
- Eval-side `path_grounding:` config, composed arm + scripted twin, `run_composed_sweep.py` path arm
- Offline path-recall gate (≥14/16) as the phase's Step-0 pre-gate
- Engine seam pushed to both remotes + pin bump (07.5-06 precedent)
- The human-run credentialed CK25 sweep + adopt/kill record

**Out of scope:**
- Catalog expansion / `synthbank` v2 (multi-column, AVG/SUM, top-K, GROUP-BY-project) — targets the *wrong-value* bucket, a separate lever
- Fine-tuning — schema-specific, breaks CDF transfer; fallback only if in-context path-teaching plateaus
- Judge relaxations (ASK-true ≡ SELECT-nonempty, row-level F1 partial credit) — real but separate/opportunistic eval work
- QALD lift — bottleneck is orthogonal entity grounding at DBpedia scale
- Path depth ≥ 4 — the two 4-hop supply-chain golds (ck25-47/48) are logged as a known limitation, not targeted
- Significance-gated grading — CK25 n=49 (~16–20pt MDE) can't reliably detect it

## Constraints

- **Engine purity:** the seam is stdlib-only and MUST NOT import `pyoxigraph` (test-only dep, D-08); mechanically TBox-derived, no per-schema hand-curation (transfers to CDF; Cypher inherits).
- **Anti-distraction budget:** at most 5 paths surfaced per question; the render surface stays small by design (the ≤5 budget is the specific control for the 07.4 distraction regression).
- **Composition:** reuses seam-6 (anchor class) and seam-7 (target token scorer); does not modify their behavior.
- **Determinism:** path ordering is deterministic (length → question-token overlap → lexical signature).
- **No-regression:** W3C DAWG query-eval coverage ≥ 96.4%; SPARQL→AQL transpiler package unchanged.
