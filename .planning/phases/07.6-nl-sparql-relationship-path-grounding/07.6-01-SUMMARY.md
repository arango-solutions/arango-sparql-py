## Decisions Made

- **Target matching is dual-mode** (predicate local name OR class local name): several of the 16 gold cases terminate in a DATATYPE attribute (email, addressLocality, reliabilityIndex) that `ClassPathIndex` — an object-property-only graph — can never represent as an edge. The gold fixture instead targets the connecting OBJECT property that reaches the class carrying that attribute (e.g., `memberOf` for email, reaching `Agent`), consistent with the design's division of labor: seam-8 navigates to the right CLASS, seam-7 (a later plan's concern) surfaces the terminal attribute itself.
- **Two cases (ck25-35, ck25-50) have no real seam-6 instance anchor** (both are open aggregate/relational queries, not "find X of a named entity"). The gold fixture anchors them on the question's naturally implied domain class (`Product`, `Department`) rather than excluding them — this matches the scope doc's own framing of ck25-35 as the D-10 self-loop worked example.
- **`candidates_dump.json` committed this plan**: it's Phase 07.5's `dump_candidates.py` output, generated in a prior session but never checked into git. `derive_path_golds.py` depends on it existing for reproducibility (CI, fresh clones), so it was committed alongside Task 2's other files (Rule 3 — blocking issue, missing referenced input).

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Component-level visited-tracking incorrectly blocked the canonical inverse-join case**
- **Found during:** Task 1, immediately after writing the initial implementation and running it against the real CK25 TBox (`test_canonical_inverse_join_recovered` failed with an empty result).
- **Issue:** An early design used the D-9 subclass-merged component id (not the literal class name) for path-enumeration visited-tracking, to prevent a spurious "bounce between subclass-linked aliases" padding path a synthetic unit test had surfaced (`Unit -> Container -> Zone -> Widget` when `Zone`/`Unit` share one effective adjacency list). That fix over-corrected: since `Employee`/`Manager`/`Agent` are ALL one merged component (Manager ⊑ Employee ⊑ Agent), it also blocked the genuinely meaningful narrowing hop `Agent -[hasManager]-> Manager` the moment `Agent` was first visited — silently breaking the canonical ck25-7 recovery this whole plan exists to prove.
- **Fix:** Reverted to LITERAL-class-name visited-tracking (the original design). The harmless side effect (an occasional non-minimal, redundant longer path to an already-reachable target) is accepted: the deterministic `(length, ...)` sort always ranks a true shorter path ahead of it, so it never displaces a correct minimal answer. The one synthetic unit test that had assumed strict list equality was loosened to assert the minimal path is *present* (and first, since length is the primary sort key), not that it's the *only* result.
- **Files modified:** `~/dev/arango-query-core/arango_query_core/nl/pathindex.py`, `~/dev/arango-query-core/tests/test_nl_pathindex.py`
- **Verification:** `test_canonical_inverse_join_recovered` passes against the real CK25 TBox; all 14 engine unit tests + full 133-test engine suite green.
- **Committed in:** Amended into `arango-query-core@30ac7f5` (Task 1's engine commit) before it was ever pushed — see note under Task Commits.
