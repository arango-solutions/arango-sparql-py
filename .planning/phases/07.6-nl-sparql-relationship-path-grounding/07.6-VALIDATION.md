## Sampling Rate

- **After every task commit:** engine-side unit tests (`uv run pytest tests/test_nl_grounding.py -x` or sibling, in the `arango-query-core` checkout) — fast, offline, no key.
- **After every plan wave:** R4 recall gate + `--dry-run` composed-arm smoke + the parity test + `tests/w3c/test_coverage_gate.py` — all offline, always-on, no key.
- **Phase gate (before adopt/kill):** full offline suite green (R1–R4 automated) BEFORE the human-run credentialed sweep (R5) is requested.
- **Max feedback latency:** ~60s offline (the credentialed sweep is deliberately out of the fast loop — it is the terminal directional measurement, human-run).

## Security Domain

- **V5 Input Validation (applies):** reuse `_sanitize_label`/`_local_name` (`grounding.py:66-94`) for every rendered class/predicate label in the path renderer — same control-char-strip + length-cap discipline already proven against T-07.3-01/T-07.4-01.
- **Threat — prompt injection via a maliciously labeled TBox class/predicate** rendered into the path-hint block (STRIDE: Tampering / Information Disclosure) → mitigation: `_sanitize_label` (mirrors `test_label_sanitization`/`test_predicate_label_sanitization`, `arango-query-core/tests/test_nl_grounding.py:73-93,299-317`).
- **Threat — schema-dump distraction** (prompt-integrity concern; the 07.4 regression) → mitigation: the ≤5-path global-pool budget (D-03) + the zero-regression credentialed-sweep gate (R5). This phase's design IS the mitigation for the previously observed instance.
