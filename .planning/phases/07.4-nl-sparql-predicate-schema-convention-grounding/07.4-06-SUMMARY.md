## Accomplishments

- Root-caused and fixed the actual bug behind CR-01: `_token_substring_retrieve`'s `if hits:` guard dropped every zero-overlap predicate regardless of `k`, so "dump mode" (widening `k` to the total predicate count) was a no-op — a real CK25 question only ever surfaced 1–8 of 30 predicates.
- Added a real `dump: bool = False` escape hatch upstream in `arango_query_core.nl.grounding`, TDD RED→GREEN, with `LabelIndex`/entity grounding (seam 6) proven byte-behavior-unchanged.
- Rewrote the misleading upstream unit test that only "proved" k-alone dumping because its fixture question happened to token-match every predicate in the set.
- Pushed the fix to both `arthurkeen` and `origin` remotes (SHA `b66932046a102898e8fff205a7ddcbedfb2c896e`), verified fetchable via `git ls-remote` on both before re-pinning.
- Bumped this repo's pin at both `pyproject.toml` extras sites (`nl` and `nl[dense]`), re-locked with `uv lock`, re-synced with `uv sync --all-extras`, confirmed `PredicateIndex` importable.
- Wired `predicate_prompt_section` in both `adapter.py` and `engine_adapter.py` to pass `dump=is_dump`, keeping the two adapters' rendered output and executable logic byte-identical (comments still legitimately differ, as they did pre-existing).
- Re-ran all required offline verification: both scripted plumbing gates (CK25 predicate-grounded, CK25 grounded+predicate-grounded, QALD-9-plus predicate-grounded — all `pass_rate=1.0`), the cross-adapter parity test, the engine prompt test, the full `tests/nl2sparql/` suite (179 passed / 603 skipped, unchanged from the review's baseline), and the W3C coverage gate (green). `arango_sparql/translate/` diff is empty.
- Annotated (not reversed) the existing NL-ACC-02 documented-null closure as provisional/confounded in `REQUIREMENTS.md`, `baseline.json`, and the eval README, since the recorded null ran against the broken dump mode and needs re-confirmation by a fresh live sweep.
- Did **not** run any credentialed/live `RUN_EVAL` sweep — that re-run is a separate human checkpoint, per explicit instruction.

## Decisions Made

- Threaded `dump` as a keyword-only bool through the shared scorer rather than adding a separate dump-only method — keeps `LabelIndex` and `PredicateIndex` on the exact same code path, with `dump=False` as the default preserving byte-identical prior behavior for both.
- Used a question with no shared domain token (`"what is the price"`, omitting "product") when testing that dump-mode ranking still favors real hits — an earlier draft used a question containing "product," which both the price and category fixture predicates matched via their shared `domain="Product"`, making the assertion fragile/coincidental rather than a clean test of the ranking rule.
- Rebased the two new upstream commits onto a `style: ruff format` commit that landed on `main` between the initial fetch and the push (both remotes had already advanced past the previously-recorded `8adc0de` pin) rather than force-pushing — this is the correct, non-destructive way to publish onto a shared branch that moved.
- Chose to annotate rather than reverse the existing NL-ACC-02 documented-null closure: the plan's instructions were explicit that no live sweep should run in this session, and unilaterally flipping a requirement's closed status without new experimental evidence would be a bigger claim than the fix itself supports.
