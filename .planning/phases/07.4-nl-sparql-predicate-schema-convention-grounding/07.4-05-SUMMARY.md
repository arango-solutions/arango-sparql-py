## Decisions Made

- **Kept the standalone regression and the additive wash as two separate, clearly-labeled findings** rather than blending them into one number — the plan's actual design composes seam-7 additively (after seam-6 in `NLQueryEngine._system_prompt`), so the additive arm is the real NL-ACC-02 hard-gate test; the standalone arm is reported honestly as a secondary characterization of seam-7's isolated (and negative) effect.
- **Did not fabricate a `cases` dict** for the additive CK25 arm or either QALD arm — only aggregate pass-rate + a single paired McNemar/bootstrap pairing was pasted back for those three (no full per-case verdict dict), so they live under a new `phase07_4_predicate_grounding_sweep` sibling key mirroring the existing `phase07_dense_few_shot_sweep` precedent (`BaselineConfig.cases` is a required field; inventing values to satisfy the schema would fabricate data).
- **b/c letter assignment**: kept consistent with the NL-ACC-01 file convention (`b` = gained_0_to_1, `c` = regressed_1_to_0) for the standalone arm's `confirmatory_test`, i.e. `b=0, c=7`, even though the human/orchestrator's paste-back described the same 7 cases as "`b=7` regressions, `c=0` improvements" (opposite letter assignment). The exact two-sided McNemar p-value is symmetric in b/c (`p = 0.015625` either way), so this is a labeling choice for internal file consistency, not a different statistical result — verified by independently recomputing via `runner.py::paired_mcnemar`'s own algorithm.
- **NL-ACC-02 closed via the documented-null path**, matching the exact convention observed in `NL-FEW-02`'s actual closure (`[x]` + traceability `Complete`, with the honest null narrated inline in the requirement bullet) rather than inventing a distinct "Closed-null" status label that doesn't exist elsewhere in the file.
