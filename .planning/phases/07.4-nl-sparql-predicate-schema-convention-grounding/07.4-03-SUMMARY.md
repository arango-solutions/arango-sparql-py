This is exactly the honest finding RESEARCH.md anticipated, not a bug.

**3. [Rule 1 - Bug] Task 3's literal automated verify command (`idx.retrieve('', 10**6)`) is unsatisfiable regardless of implementation, due to a property of the shared (pinned, out-of-scope) token-substring scorer**
- **Found during:** Task 3 verification -- running the plan's exact verify text (`n=len(list(idx.retrieve('', 10**6))); assert n>40, n`) against the real QALD fixture raised `AssertionError: 0`.
- **Issue:** Root-caused empirically (not assumed): `arango_query_core.nl.grounding._token_substring_retrieve` computes hits by checking (a) whether the label's own tokens appear in the question string, and (b) whether the question's tokens appear in the label -- with an **empty** question string, `q_tokens` is the empty set and no nonempty label-token substring can ever be found "in" `""`. Both directions are vacuously false for *every* item regardless of that item's labels, so `.retrieve("", k)` always returns `[]`, independent of `k` and independent of how many predicates the index actually holds. This is a property of the already-pinned, sibling-repo `PredicateIndex`/`LabelIndex` shared scorer (not something introduced or fixable by this in-repo-only plan).
- **Fix:** The test I wrote (`test_predicate_qald_dbpedia_subset_shape_distribution_recorded_honestly`) instead reads `len(index._predicates)` directly -- the same private-attribute-read mechanism `arango_sparql/nl2sparql/{engine_adapter,adapter}.py`'s own D-01 dump/retrieve threshold check already uses (established precedent, documented in `07.4-02-SUMMARY.md`: "`PredicateIndex` has no public `__len__`/`count()`"). This satisfies the actual acceptance criteria ("build_predicate_index runs against `dbpedia_subset.ttl` without crashing and returns >40 predicates (retrieve path exercised on a real fixture)") via the correct, already-established mechanism; the plan's ad-hoc `-c` shell invocation with `.retrieve('', ...)` was illustrative shorthand, not itself a required gate (no acceptance-criteria bullet mandates that exact one-liner's literal success).
- **Files modified:** none beyond the plan's own scope (test logic only).
