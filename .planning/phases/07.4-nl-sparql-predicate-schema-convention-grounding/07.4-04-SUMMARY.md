## Accomplishments

- `runner.py::run()`: added the `predicate_grounding:` config-key read (`predicate_cfg`/`predicate_k`/`predicate_index`), gated on `if predicate_cfg and shared_ontology:` (NOT `data_ttl` -- Pitfall 5, QALD has no `data_path`), building the `PredicateIndex` ONCE via a function-locally-imported `build_predicate_index(shared_ontology)` before the per-case loop, then threading `predicate_k=predicate_k, predicate_index=predicate_index` into every case's `NlPipeline(...)` construction.
- Applied the D-05 fix in `write_report()`: the JSON payload's per-case dict literal now includes `"sparql": c.actual` (the already-populated generated SPARQL string) alongside `name`/`passed`/`elapsed_ms` -- a one-key addition, not new plumbing.
- Added four net-new `configs.yml` entries: `scripted-ck25-predicate-grounded` + `openai-gpt4o-mini-ck25-predicate-grounded` (`predicate_grounding: {k: 40}`, CK25's 30 properties sit under `PREDICATE_DUMP_THRESHOLD`) and `scripted-qald9plus-predicate-grounded` + `openai-gpt4o-mini-qald9plus-predicate-grounded` (`predicate_grounding: {k: 20}`, QALD's 250 properties exercise the genuine retrieve path). The pre-existing `openai-gpt4o-mini-qald9plus` zero-shot config was left untouched (verified: still appears exactly once).
- `test_grounding_engine_prompt.py`: added `test_predicates_render_in_engine_prompt_not_standalone_builder` -- a hand-rolled `PredicateIndex`/`GroundedPredicate` fixture proves `"## Known schema predicates"` appears in `NLQueryEngine._system_prompt(question, "")` and is absent from `SparqlAdapter.grammar_prompt_section("")` (D-07 cache-boundary discipline extended to seam 7).
- `test_grounding_prompt_parity.py`: added `test_predicate_prompt_section_byte_identical_across_adapters` -- the same `PredicateIndex` fixture rendered via both `SparqlAdapter.predicate_prompt_section` and `SparqlLanguageAdapter.predicate_prompt_section` produces byte-identical output.
- `test_grounding_recall.py`: added `test_predicate_retrieval_recall_meets_mechanical_builder_floor` -- builds a `PredicateIndex` from CK25's `shared_ontology` (via `build_predicate_index`, not the instance-graph `build_label_index` the sibling entity guard uses), scans every gold SPARQL for `pv:[A-Za-z]+` mentions, and asserts `PredicateIndex.retrieve(case["nl"], k=40)` recall against those mentions meets a floor. Measured 78/158 = 0.49 (recorded honestly, not aspirational); floor asserted at 0.45 (below measured, headroom). Always-on CI tier (no `RUN_EVAL`/`pytest.mark.eval`).
- Verified both scripted plumbing gates run end-to-end without crashing: `scripted-ck25-predicate-grounded` (pass_rate 1.0, 49/49) and `scripted-qald9plus-predicate-grounded` (pass_rate 1.0, 514/514) -- config -> `build_predicate_index` -> seam 7 -> prompt -> judge, all wired correctly. Both report `pass_rate` 1.0 because the scripted client replays each case's own gold answer regardless of prompt content -- this is plumbing evidence, not accuracy evidence (mirrors the 07.3-05 `scripted-ck25-grounded` precedent).
