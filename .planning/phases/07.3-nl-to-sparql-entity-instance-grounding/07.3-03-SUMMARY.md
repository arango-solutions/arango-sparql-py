# Phase 07.3 Plan 03: SparqlAdapter seam-6 wiring + verbatim grounding wording Summary

**Wired SparqlAdapter as the first consumer of engine seam 6 (grounding_index/grounding_prompt_section with the verbatim spike "use these EXACT IRIs" wording), threaded grounding_k/grounding_index through NlPipeline, added the SC-gate proving the block is engine-composed and never leaks into the cacheable grammar prefix, and fixed a pre-existing regression in the legacy nl_to_sparql() adapter that the 07.3-02 pin bump had silently broken.**

## Performance

- **Duration:** ~35 min
- **Completed:** 2026-07-23
- **Tasks:** 3/3 completed
- **Files modified:** 5 (2 plan-scoped source files, 1 plan-scoped test file modified, 1 new test file, 1 out-of-scope Rule-3 fix)

## Accomplishments

- `SparqlAdapter.__init__` gained a keyword-only `grounding_index: LabelIndex | None = None` param, stored as `self._grounding_index`.
- `SparqlAdapter.grounding_index()` (seam 6) returns the injected index, or `None` when none was injected — explicit-injection-only, no production-default fallback (per RESEARCH Open Question 2).
- `SparqlAdapter.grounding_prompt_section(question, index, k=20)` delegates to `LabelIndex.format_prompt_section(...)`, supplying the verbatim spike header `"## Known entities (use these EXACT IRIs)"` + instruction text and `id_prefix="<"`/`id_suffix=">"` so IRIs render as `<IRI> — "label" (type)`.
- Class docstring seam table extended with a `grounding_index` / `LabelIndex` row.
- `NlPipeline.__init__` gained `grounding_k: int = 20` / `grounding_index: LabelIndex | None = None`, stored and threaded into the `SparqlAdapter(...)`/`NLQueryEngine(...)` construction inside `run()` — mirrors the existing `few_shot_k`/`few_shot_index` plumbing exactly. Default behavior is byte-identical when `grounding_index` is omitted (verified: existing `test_pipeline.py` stays green, 14/14).
- `tests/nl2sparql/test_grounding_engine_prompt.py` (new): sentinel-labeled `GroundedEntity` injected into `SparqlAdapter` → `NLQueryEngine._system_prompt(f"find the {SENTINEL}", "")` contains `"## Known entities"` + the sentinel label; `adapter.grammar_prompt_section("")` contains NEITHER — proving the Pitfall 1 cache-boundary invariant holds (grounding never leaks into the static/cacheable schema prefix).
- `tests/nl2sparql/test_engine_adapter.py`: added `test_grounding_index_returns_injected_index` and `test_grounding_index_defaults_to_none` to `TestSparqlAdapterSeams`.
- **Rule 3 fix (out-of-plan-scope, required for the plan's own verification gate):** the legacy `SparqlLanguageAdapter` (`arango_sparql/nl2sparql/adapter.py`, used only by the library-facing `nl_to_sparql()` entry point) did not implement seam 6. Since the 07.3-02 pin bump added `grounding_index()`/`grounding_prompt_section()` to the `QueryLanguageAdapter` Protocol and `NLQueryEngine._system_prompt()` now calls `adapter.grounding_index()` unconditionally, this adapter broke with `AttributeError: 'SparqlLanguageAdapter' object has no attribute 'grounding_index'` on every call — 3 pre-existing failures in `tests/nl2sparql/test_adapter.py`, confirmed present at 07.3-02's HEAD (`946fc97`) before any Plan 03 task ran. Fixed by adding the same explicit-injection-only seam 6 (`_grounding_index` dataclass field + `grounding_index()`/`grounding_prompt_section()` methods) mirroring `engine_adapter.SparqlAdapter` byte-for-byte, including the verbatim wording.
- Verified non-regression: `git diff --stat -- arango_sparql/translate/` empty across all three task commits; full offline `tests/nl2sparql/` suite green (166 passed, 603 skipped); `tests/nl2sparql/ -k grounding` (3 passed); W3C coverage gate (`tests/w3c/test_coverage_gate.py`) still green.
