# Phase 07.3 Plan 05: Wire additive `grounding:` config into the eval harness Summary

**Additive `grounding:` config key wired end-to-end: runner.py builds a LabelIndex once per run from the corpus's vendored CK25 instance graph and threads it into every case's NlPipeline; configs.yml gains scripted-ck25-grounded (green plumbing gate, pass_rate 1.0/49) + openai-gpt4o-mini-ck25-grounded, with `pv:name` confined entirely to declarative config.**

## Performance

- **Duration:** ~12 min
- **Tasks:** 2/2 completed
- **Files modified:** 2

## Accomplishments
- `runner.py::run()` now reads an additive `grounding:` config key (`k`, `label_predicates`), builds the `LabelIndex` exactly once per run (before the per-case loop) from `data_ttl`, and passes `grounding_k`/`grounding_index` into every case's `NlPipeline` construction — same shape as the existing `few_shot:` build-once precedent.
- Global default `label_predicates` is `["rdfs:label"]`; no dataset-specific predicate is hardcoded in runner.py logic (net-new `pv:name` contribution to the file is 0 — see Issues Encountered).
- `configs.yml` gains `scripted-ck25-grounded` and `openai-gpt4o-mini-ck25-grounded`, placed directly after the existing `openai-gpt4o-mini-ck25` entry, each with `grounding: {k: 20, label_predicates: ["rdfs:label", "pv:name"]}`.
- `scripted-ck25-grounded` verified green as a plumbing gate under `RUN_EVAL=1`: `pass_rate=1.0` over all 49 CK25 cases — proves the config → `build_label_index` → seam 6 → prompt → execution judge path doesn't crash; explicitly documented as plumbing evidence, not accuracy evidence (Pitfall 5).
- Every pre-existing config in `configs.yml` is untouched (purely additive diff, confirmed via `git diff`); `test_ci_gate_only_ever_runs_scripted` stays green under both plain and `RUN_EVAL=1` invocations.
