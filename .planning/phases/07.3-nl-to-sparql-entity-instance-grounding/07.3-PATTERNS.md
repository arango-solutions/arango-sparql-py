### `arango_query_core/nl/grounding.py` (NEW — service/retrieval index)

**Analog:** `arango_query_core/nl/fewshot.py` (`Retriever` protocol, `FewShotIndex` class)

**Imports pattern** (fewshot.py lines 22-30):
```python

Grounding needs `dataclass`/`field` instead of the corpus-file-loading imports (`Path`/`yaml`-adjacent) since the index is built by the *caller* from a `list[GroundedEntity]`, not loaded from a YAML corpus file itself.

**Core retrieval-index pattern** — mirror `FewShotIndex`'s exact shape: a plain constructor taking pre-built data (`__init__(self, entities: list[GroundedEntity])`), a `retrieve(question, k) -> list[...]` method, and a `format_prompt_section(question, k, **kwargs) -> str` method that returns `""` when there are no matches (fewshot.py lines 283-304):
```python
def retrieve(self, question: str, k: int = 3) -> list[tuple[str, str]]:
    return self._retriever.retrieve(question, k=k)

def format_prompt_section(self, question: str, k: int = 3, *, language: str = "") -> str:
    matches = self.retrieve(question, k=k)
    if not matches:
        return ""
    lines = ["## Examples"]
    for nl, query in matches:
        lines.append(f"Q: {nl}")
        lines.append(f"```{language}")
        lines.append(query.strip())
        lines.append("```")
    return "\n".join(lines)
```
The RESEARCH.md `LabelIndex`/`GroundedEntity` code block (§ Architecture Patterns Pattern 1, lines 268-336) is the exact target implementation — it already follows this shape (`retrieve()` returns `list[GroundedEntity]`, `format_prompt_section()` returns `""` on empty, header/instruction/id_prefix are caller-parameterized exactly like `language=` is on `FewShotIndex.format_prompt_section`). Port that block verbatim; it is itself a direct port of `scratchpad/nl-grounding-spike/grounding_spike.py::retrieve()` (lines 99-123) and `entity_block()` (lines 126-139).

**No memoization needed at this layer** — unlike `cached_few_shot_index` (fewshot.py lines 307-319), `LabelIndex` construction is caller-owned (the eval harness builds it once in `runner.py::run()`); do not add an `lru_cache`-wrapped factory inside `grounding.py` itself, since there is no single canonical "bank path" the way there is for few-shot (grounding data varies per corpus/deployment). This mirrors the RESEARCH.md Pitfall 3 guidance — the "build once" discipline lives in the *caller* (`runner.py`), not baked into the module.

### `tests/nl2sparql/eval/grounding_index_builder.py` (NEW, eval-only pyoxigraph builder)

**Analog:** `runner.py::_build_label_map` (lines 355-377) for the query/normalization shape + `scratchpad/nl-grounding-spike/grounding_spike.py::build_entity_index` (lines 75-96) for the exact per-entity aggregation logic

**Pattern to copy** (spike lines 75-96, restructured to return `LabelIndex` instead of `list[dict]`):
```python
def build_label_index(data_ttl: str, label_predicates: list[str]) -> LabelIndex:
    from tests.helpers.oxi import load_store_from_string, oxi_query
    store = load_store_from_string(data_ttl)
    predicate_union = "|".join(f"<{p}>" for p in label_predicates)
    q = f"""
    SELECT ?s ?label ?type WHERE {{
      ?s ({predicate_union}) ?label .
      OPTIONAL {{ ?s a ?type }}
    }}"""
    by_iri: dict[str, dict] = {}
    for row in (oxi_query(store, q).rows or []):
        iri = row.get("s")
        if not iri:
            continue
        label = (row.get("label") or "").strip('"').split('"^^')[0]
        e = by_iri.setdefault(iri, {"labels": set(), "type": ""})
        if label:
            e["labels"].add(label)
        if row.get("type") and not e["type"]:
            e["type"] = row["type"].rsplit("/", 1)[-1].rstrip(">")
    from arango_query_core.nl.grounding import GroundedEntity, LabelIndex
    return LabelIndex.from_items(
        [GroundedEntity(id=iri.strip("<>"), labels=tuple(v["labels"]), type=v["type"])
         for iri, v in by_iri.items()]
    )
```
Note: `label_predicates` is expressed as full IRIs in this function's SPARQL (`f"<{p}>"`), but `configs.yml`'s `label_predicates: ["rdfs:label", "pv:name"]` uses prefixed names — either resolve prefixes via a `PREFIX` preamble (matching the spike's literal `PREFIX pv: <...> PREFIX rdfs: <...>` header, spike lines 77-79) or expand them before interpolation; pick whichever the ontology's already-parsed prefix map makes easiest, since RESEARCH.md doesn't lock this detail (flagged as planner discretion in RESEARCH.md's Assumptions Log A2 area). **This file MUST import `pyoxigraph`-touching helpers only from `tests.helpers.oxi`, and must live under `tests/`** — never inside `arango_query_core` or `arango_sparql` (CLAUDE.md hard rule 5 / RESEARCH.md packaging boundary).

"""SC-gate: retrieved grounding entities land in the ENGINE-built prompt.

Mirrors test_fewshot_engine_prompt.py's SC2 gate for seam 6: the engine's

from arango_sparql.nl2sparql.models import LLMResponse

ONTOLOGY = """...""".strip()  # same fixture ontology as test_fewshot_engine_prompt.py

_SENTINEL_LABEL = "Sentinel Widget XYZ123"


def _build_index() -> LabelIndex:
    return LabelIndex.from_items([

```python
_IRI_RE = re.compile(r"<http://ld\.company\.org/prod-instances/[^>]+>")

def test_gold_iri_retrieval_recall_meets_spike_floor() -> None:
    corpus = _load_corpus(EVAL_DIR / "vendored/ck25/corpus.yml")
    data_ttl = (EVAL_DIR / "vendored/ck25" / corpus["data_path"]).read_text()
    index = build_label_index(data_ttl, ["rdfs:label", "pv:name"])

    hits = total = 0
    for case in corpus["cases"]:
        gold_iris = set(_IRI_RE.findall(case["expected"]))
        if not gold_iris:
            continue
        retrieved = {f"<{e.id}>" for e in index.retrieve(case["nl"], k=20)}
        hits += len(gold_iris & retrieved)
        total += len(gold_iris)

    recall = hits / total
    assert recall >= 0.90, (
        f"grounding retrieval recall regressed: {hits}/{total} = {recall:.2f} "
        f"(spike measured 24/25 = 0.96)"
    )
```
