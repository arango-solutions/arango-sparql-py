<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| instance-graph label data → LLM system prompt | `rdfs:label`/`pv:name` strings from the (potentially attacker-influenced) target instance graph are spliced verbatim into the engine-built system prompt via `format_prompt_section`. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07.3-01 | Tampering / Injection | `LabelIndex.format_prompt_section` (engine renderer) | mitigate | Sanitize every rendered label in `_sanitize_label`: strip C0 control chars + newlines to spaces, collapse whitespace, truncate to a 200-char cap; top-k=20 bounds total injected text. The delimited `## <header>` block + downstream (unchanged) rdflib `validate` seam + SchemaResolver vocabulary enforcement remain the actual AQL-emission safety net. Sanitization is verified no-op on clean CK25 labels. |
| T-07.3-01b | Tampering | prompt-block structure | accept (residual) | A sanitized label can still bias the model's word choice, but any resulting SPARQL must still PARSE (rdflib) and TRANSLATE (SchemaResolver) to yield AQL — no new AQL-emission surface is introduced beyond what few-shot/ontology text already carries. |
| T-07.3-SC | Tampering | arango-query-core git dependency content | transfer (to Plan 02) | This plan only commits locally; the supply-chain verification (both-remotes `git ls-remote` before pin bump per Pitfall 4) is owned by Plan 02. |
</threat_model>
